# Настройка подключений: пошагово

Что уже умеет дашборд (код готов, нужны только ключи):

- **Google Ads**:
  - список кабинетов под MCC появляется во «Вводных»;
  - пауза и включение кампаний из «Реклама → Аналитика»;
  - создание и запуск поисковых кампаний из «Сборки кампаний».
- **CRM**: вебхук для любой CRM или формы, Kommo/amoCRM, Bitrix24. Лиды показываются на странице проекта.
- **Google Таблицы**: импорт лидов для проектов без CRM; ежедневное заполнение таблицы «Репорт».
- **Google Drive**: папка проекта с исходниками и загрузка контента из «Креативов» и «Создания контента».
- **Журнал действий**: всё, что дашборд меняет во внешних системах, в «Настройки → Подключения».

## 1. Сервис-аккаунт Google (один на всё)

1. [Google Cloud Console](https://console.cloud.google.com) → проект, где уже живёт сервис-аккаунт агента
   (`wide-cathode-509912-k0`), или новый проект.
2. **APIs & Services → Library** → включить **Google Ads API**, **Google Sheets API**, **Google Drive API**.
3. **IAM & Admin → Service Accounts → Create service account**:
   - имя `profitad-dashboard`;
   - роли проекту не нужны.

   Агенту — свой сервис-аккаунт, дашборду — свой: доступы отзываются независимо.
4. Открыть созданный аккаунт → **Keys → Add key → Create new key → JSON**. Файл скачается — это и есть ключ.
   Никому не пересылать.
5. Записать почту аккаунта вида `profitad-dashboard@….iam.gserviceaccount.com`. Её добавляем в MCC, таблицы и
   общий диск.

## 2. Google Ads (MCC)

1. **MCC → Админ → Доступ и безопасность → «+»** → почта сервис-аккаунта → уровень **Стандартный**.
   Он нужен, чтобы создавать кампании и ставить их на паузу; «Только чтение» не подойдёт.
2. **Developer token** — тот же, что у агента: **MCC → Админ → API Center**. Уровень Basic уже одобрен.
3. ID MCC — 10 цифр в правом верхнем углу Google Ads (без дефисов).

### Как подключить нового клиента

1. **MCC → Аккаунты → «+» → Привязать существующий аккаунт** → ID кабинета клиента → «Отправить запрос».
2. Клиент принимает его у себя: **Google Ads → Админ → Доступ и безопасность → Менеджеры**.
3. **Дашборд → Вводные → проект → Источники трафика → Google Ads** → выбрать кабинет из списка.
4. Статистику по-прежнему каждый час заливает агент. Чтобы он подхватил клиента, создайте его в Telegram-боте
   командой `/new` с тем же ID кабинета и списком «что считается заявкой».

## 3. Ключи в Vercel

**Vercel → profitad-dashboard-2.0 → Settings → Environment Variables**, окружения Production, Preview, Development:

| Переменная | Значение |
|---|---|
| `GOOGLE_SERVICE_ACCOUNT_JSON` | содержимое JSON-ключа из шага 1. Удобнее в base64: `base64 -i key.json \| pbcopy` |
| `GOOGLE_ADS_DEVELOPER_TOKEN` | developer token из MCC |
| `GOOGLE_ADS_LOGIN_CUSTOMER_ID` | ID MCC, только цифры |
| `TOKEN_ENCRYPTION_KEY` | случайная строка: `openssl rand -base64 48` |
| `CRON_SECRET` | случайная строка: `openssl rand -hex 32` |

После этого:

```bash
cd ~/Desktop/PROFITAD/INHOUSE/profitad-dashboard-2.0 && npx vercel env pull .env.local --environment=production
```

Локальный дашборд работает с той же базой, поэтому `TOKEN_ENCRYPTION_KEY` локально и на Vercel должен совпадать.
Иначе сохранённые токены CRM не расшифруются. Затем Redeploy в Vercel или пуш в `main`.

Проверка: **Настройки → Подключения** — все пункты, кроме Meta, зелёные, у Google Ads показано число кабинетов.

## 4. Google Таблицы

- **Доступ:** в таблице «Поделиться» → почта сервис-аккаунта → **Редактор**.
- **Лиды (проекты без CRM).**
  - В первой строке — заголовки: Дата, Имя, Телефон, Email, Статус, Источник, Сумма (какие есть).
  - Вставьте ссылку в «Вводные → проект → Подключения → Google Таблица с лидами».
- **Репорт.**
  - Вставьте ссылку и нажмите «Найти листы». Дашборд сам находит листы с `DATE` в A1 и колонки BUDGET,
    Impressions, CLICKS, Leads, Subs.
  - На вашем шаблоне это FB - Subs и FB - Leads (данные Meta), Google (данные Google). MAIN не трогается.
  - Каждое утро (05:00 UTC) в строку с нужной датой вписываются расход, показы, клики, лиды и подписки за последние
    3 дня.
  - Формулы (CTR, CPM, CPL…) пересчитываются сами. Строки не добавляются — даты должны уже стоять в колонке A, как в
    шаблоне.

## 5. Google Drive

У сервис-аккаунта нет своего места на Drive, поэтому загрузка работает только в **общий диск (Shared Drive)**
Google Workspace.

1. **Drive → Общие диски → Создать** (например, «PROFITAD Контент»).
2. Участники → почта сервис-аккаунта → **Менеджер контента**.
3. Внутри — папка на каждый проект. Ссылку на папку вставьте в «Вводные → проект → Подключения → Google Drive».

Файлы из «Креативов» и «Создания контента» загружаются прямо в Google, минуя наш сервер, поэтому видео любого размера
проходят.

## 6. CRM

| CRM | Что вставить во «Вводные → Подключения → CRM» |
|---|---|
| **Вебхук** (любая CRM, Tilda, формы, Zapier/Make) | Ничего: нажать «Создать вебхук» и передать адрес в CRM. Поля: `name`, `phone`, `email`, `status`, `value`, `utm_*`, `created_at`, `id` |
| **Kommo / amoCRM** | Домен (`agency.kommo.com`) и долгосрочный токен: Настройки → Интеграции → Создать интеграцию → Ключи и доступы |
| **Bitrix24** | Ссылку входящего вебхука с правами CRM и «Пользователи»: Разработчикам → Другое → Входящий вебхук |

Kommo и Bitrix24 опрашиваются раз в день и по кнопке «Синхр.»: история за 90 дней при первом подключении, дальше
только изменения. Вебхук принимает лиды сразу. Токены хранятся зашифрованными, в браузер не отдаются.

## 7. Meta

У агента приложение Meta заблокировано с 30.09.2026. Запуск кампаний и постинг в Instagram, Facebook и Threads
заработают после разблокировки. Конструктор уже сохраняет кампании Meta как задания, а в таблице «Репорт» листы Meta
заполнятся, как только появятся данные.

## Для команды агентов

- Дашборд теперь сам управляет кампаниями Google через свой сервис-аккаунт. Это решение владельца от 13.11.2026,
  оно заменяет пункт «Не давать дашборду доступ к Google Ads API» из ТЗ агента.
- Выгрузка агента в `ad_metrics_daily` не меняется: таблица, колонки и первичный ключ те же.
- Схемой базы управляет drizzle (`npm run db:push`). Таблицы, которых нет в `db/schema.ts`, при пуше будут
  **удалены**. Новые таблицы из ТЗ агента (`decisions`, `shift_runs`, `content_items`…) нужно добавить в
  `db/schema.ts` дашборда, а не создавать вручную.
- Лиды из CRM лежат в `leads` (поле `outcome`: `new` / `qualified` / `won` / `lost` / `junk`) — это та самая
  «судьба заявки» из бэклога агента. Чтобы агент её видел, нужен `GRANT SELECT ON leads TO bot_sync` (в таблице есть
  телефоны и почты — выдавать осознанно).
