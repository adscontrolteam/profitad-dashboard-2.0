# Подключение рекламы и соцсетей

> Как настроить то, что уже сделано (Google Ads, Таблицы, Drive, CRM): [setup-connections.md](setup-connections.md).

## Главная идея: подключаем агентство один раз, а не каждого клиента

Мы агентство, поэтому не логинимся в кабинет каждого клиента. Клиент выдаёт доступ **нашему бизнесу**, а дашборд
работает через один служебный доступ агентства. Новый проект — это выбор кабинета из списка, без токенов и паролей.

| Источник | Как клиент даёт доступ | Что подключаем мы (один раз) | Нужен вход клиента |
|---|---|---|---|
| **Meta Ads** | Добавляет наш Business Manager партнёром на рекламный аккаунт | Приложение Meta + **System User** нашего BM | Нет |
| **Facebook-страницы** | Партнёрский доступ к странице в нашем BM | Тот же System User | Нет |
| **Instagram** (бизнес-аккаунт, привязан к странице) | Партнёрский доступ к странице или к аккаунту Instagram в нашем BM | Тот же System User | Нет |
| **Google Ads** | Принимает приглашение от нашего **MCC** (управляющего аккаунта) | Developer token + OAuth сотрудника с доступом к MCC | Нет |
| **Threads** | — (Threads не работает через Business Manager) | Приложение Threads | **Да**, по ссылке |
| **TikTok** | — | Приложение TikTok for Developers | **Да**, по ссылке |
| **YouTube Shorts** | Можно добавить нас менеджером канала, но API всё равно требует вход владельца | Проект Google Cloud | **Да**, по ссылке |

«По ссылке» значит, что дашборд создаёт для проекта **ссылку подключения** на 7 дней. Клиент открывает её без
регистрации, нажимает «Подключить TikTok» и входит в **своём** TikTok. Нам приходит токен, пароль мы не видим.

## Безопасность

1. **Ни одного пароля.** Только партнёрские доступы в BM и MCC, а для остального — официальный OAuth.
2. **Токены только на сервере и только зашифрованные.**
   - Шифрование AES-256-GCM, ключ `TOKEN_ENCRYPTION_KEY` в env Vercel.
   - В браузер токены не уходят никогда.
   - Утечка базы без ключа бесполезна.
3. **Минимум прав.** Сначала подключаем только чтение (`ads_read`, insights). Права на запись (`ads_management`,
   `*_content_publish`) включаем, когда дойдём до запуска рекламы и постинга.
4. **Кто может подключать.** Подключения агентства и ссылки для клиентов — только Администратор. Выбрать кабинет из уже
   доступных при создании проекта — тоже только Администратор: «Вводные» доступны лишь ему.
5. **Права на действия проверяются на сервере.**
   - Запустить или остановить кампанию: `canManageAds`.
   - Опубликовать пост: `canPublishContent`.
   - Каждое такое действие пишется в журнал: кто, что, когда, ответ API.
6. **Ссылки для клиентов одноразовые:** случайный токен, срок 7 дней, привязка к одному проекту. Админ может отозвать
   ссылку в любой момент.
7. **Отзыв доступа:** «Отключить» удаляет токен у нас и отзывает его у платформы, где это возможно. Если клиент сам
   снимет партнёрский доступ, синк это заметит и пометит источник «нет доступа».
8. **Требования Meta для проверки приложения:** верификация бизнеса, страница политики конфиденциальности и
   callback удаления данных (`/api/meta/data-deletion`).
9. **Синк защищён:** cron-эндпоинты принимают только `CRON_SECRET` от Vercel Cron.

## Как данные попадают в дашборд

```
Vercel Cron (каждый час)
  └─ /api/sync/ads      → Meta insights / Google GAQL за последние 3 дня (догоняем поздние конверсии)
                         → upsert в ad_metrics_daily → revalidateTag(project)
  └─ /api/sync/social   → статистика аккаунтов и последних постов → social_metrics_daily
При подключении нового кабинета → сразу тянем 90 дней истории
```

- **Привязка к проекту** — по ID кабинета (`act_…`, customer id Google) из «Источников» проекта.
- **Что считается результатом.**
  - Meta: событие, указанное у проекта («Лиды», «Подписчики», «Покупки»). Берётся из `actions` по типу
    (`lead`, `onsite_conversion.messaging_first_reply`, `offsite_conversion.fb_pixel_purchase` и т. д.).
  - Google: conversion action, выбранный у проекта.
  - Это настраивается в карточке источника, по умолчанию берётся по цели проекта.
- **Валюта:** храним в валюте кабинета и показываем её. Пересчёт в $ — позже, если понадобится.

## «Вводные»: новый проект за минуту

**Шаг 1. Проект.**
- Название.
- Цель: одна кнопка из «Лиды», «Продажи», «Подписчики», «Сообщения». По цели сами подставляются метрика результата
  и событие для синка.
- План и цена результата — по желанию.
- Период по умолчанию — текущий месяц.

**Шаг 2. Источники.** Ничего не нужно вводить вручную, только выбрать:
- **Рекламные кабинеты.** Выпадающий список с поиском по всем кабинетам, к которым у агентства есть доступ (Meta и
  Google вместе): название, ID, валюта, статус. Кабинеты, уже занятые другим проектом, помечены.
- **Страницы и Instagram.** Список из нашего BM, отмечаем галочками.
- **Threads / TikTok / YouTube.** Кнопка «Ссылка для клиента» копирует ссылку подключения, её можно сразу отправить в
  мессенджер. Пока клиент не подключился, источник висит «ждём клиента».
- **Если нужного кабинета нет в списке**, кнопка «Как выдать доступ» открывает готовую инструкцию для клиента с ID
  нашего BM или MCC — скопировать и отправить.

**Шаг 3. Команда.** Ответственные SMM и MediaBuyer (уже есть).

**Сохранить.** Проект появляется сразу, синк истории запускается в фоне. Через минуту-две на дашборде реальные цифры.

Отдельная страница **Настройки → Подключения** (только для Администратора):
- статус подключений агентства: Meta System User, Google MCC, приложения Threads, TikTok и YouTube;
- когда истекают токены;
- последний успешный синк и ошибки по каждому кабинету.

## Новые таблицы

| Таблица | Поля (главное) |
|---|---|
| `connections` | provider, scope (`agency` / `project`), project_id, external_id, name, token (зашифрован), refresh_token (зашифрован), expires_at, scopes, status, last_sync_at, last_error |
| `connect_links` | token_hash, project_id, providers, expires_at, used_at, created_by |
| `project_sources` | project_id, provider, external_id (кабинет, страница, аккаунт), connection_id, result_event, status (`ok` / `no_access` / `waiting_client`) |
| `social_metrics_daily` | date, project_id, provider, account_id, followers, views, likes, comments, shares, saves, posts |
| `audit_log` | at, actor_email, action, target, result |

Сейчас источники хранятся в `projects.sources` (jsonb). Перенесём их в `project_sources`, старое поле пока оставим для
совместимости.

## Порядок работ

| Этап | Что получится | С вашей стороны | Время разработки |
|---|---|---|---|
| **1. Meta Ads, чтение** | Синк расходов и результатов, выбор кабинета из списка в мастере проекта, страница «Подключения» | Приложение Meta в нашем BM, System User с доступом к рекламным аккаунтам, его токен | 2–3 дня |
| **2. Google Ads, чтение** | То же для Google | MCC; заявка на developer token (Basic access, проверка у Google занимает от нескольких дней); вход сотрудника с доступом к MCC | 2 дня + ожидание токена |
| **3. Facebook и Instagram** | Аналитика SMM по страницам и Instagram из нашего BM | Партнёрские доступы к страницам; проверка приложения Meta для `instagram_*` и `pages_*` | 2 дня + проверка Meta |
| **4. Ссылки для клиента** | Threads, TikTok, YouTube: подключение по ссылке и их аналитика | Аккаунты разработчика TikTok и Google Cloud, приложение Threads | 3 дня |
| **5. Запись** | Пауза и включение кампаний, создание кампаний, постинг | Расширенные права в проверке приложений | по отдельному плану |

Этап 1 даёт настоящие цифры по рекламе уже на этой неделе. Для старта с System User в собственном BM обычно хватает
стандартного уровня доступа Meta, расширенный нужен при упоре в лимиты запросов или для права на запись.

## Ключи в env (Vercel → Settings → Environment Variables)

`TOKEN_ENCRYPTION_KEY`, `CRON_SECRET`, `META_APP_ID`, `META_APP_SECRET`, `META_SYSTEM_USER_TOKEN`, `META_BUSINESS_ID`,
`GOOGLE_ADS_DEVELOPER_TOKEN`, `GOOGLE_ADS_LOGIN_CUSTOMER_ID` (MCC), `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`,
`THREADS_APP_ID`, `THREADS_APP_SECRET`, `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`.

Секреты кладёт Администратор в Vercel, в код и чат они не попадают. Токен System User можно вставить и через
страницу «Подключения»: тогда он сохраняется в базе в зашифрованном виде.
